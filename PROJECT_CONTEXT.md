# Общий контекст Шёпота

Codex и Claude используют одни источники. Обновляй источник факта, а не отдельные пересказы для каждого инструмента.

## Источники

| Источник | Что определяет |
|---|---|
| `README.md` | Возможности продукта в выбранной версии |
| `PRD.md` | Утверждённые требования и приёмку версии 1.0 |
| Task Hub, проект «Шёпот» | Текущие задачи, зависимости, решения владельца и результаты |
| `TASKS.md` | Этапы плана и копию статусов Task Hub |
| `VALIDATION.md` | Выполненные проверки и их границы для выбранной версии |
| `CLAUDE.md` | Архитектуру, команды и ограничения разработки для обоих инструментов |
| `RELEASE_NOTES.md` | Изменения конкретного выпуска |

Перед задачей проверь рабочую копию, ветку, изменения и `taskhub_status` с её путём.
Читай требования и проверки из версии, с которой работаешь. Сначала проверь наличие PRD.md и TASKS.md: они могут оставаться в отдельной ветке.

## Локальная память и состояние

Общий локальный контекст — `.private/project-context/CONTEXT.md` в основной рабочей копии.
Он содержит решения, ссылки на память Claude и историю Codex, снимок Task Hub, карту рабочих копий и установленную версию.

В worktree выполни `git rev-parse --path-format=absolute --git-common-dir`.
Папка над полученным каталогом `.git` — основная рабочая копия этого проекта.
Прочитай её `.private/project-context/CONTEXT.md`; недостающие плановые документы ищи там и в указанных ветках.
Если локального контекста нет, используй доступные источники и явно отметь пробел. Не создавай сведения по памяти.

Личные записи, расшифровки, настройки, модели и снимки памяти остаются локально. Не добавляй их в Git.

## Актуальность

Последние инструкции владельца имеют приоритет над старой памятью и планами.
Общий рабочий процесс этого Windows-профиля задан в `%USERPROFILE%/.codex/PROJECT_WORKFLOW.md`; личные инструкции каждого инструмента сохраняют свою роль.
Текущие статусы бери из Task Hub. TASKS.md обновляй в основной копии, сохраняя чужие правки.
Снимок состояния фиксирует дату проверки. Перед продолжением сверяй ветки, изменения, задачи и запущенную версию заново.

После задачи обнови затронутые источники и локальный контекст. Не заменяй историю снимком текущего состояния.
Выполни проверки по изменению и loop-code-review после каждой задачи. Завершённую задачу закрой сам после проверок.
Разрешение на Git не заменяет разрешение на установку, тег или выпуск приложения.
